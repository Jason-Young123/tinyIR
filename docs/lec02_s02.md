开发者在内存中创建、查询、替换和删除 Operation，之后再 lowering 到 LLVM IR、
GPU/NPU IR 或目标机器码。

内容：

```mlir
module {
  func.func @add_one(%x: i32) -> i32 {
    %c1 = arith.constant 1 : i32
    %y = arith.addi %x, %c1 : i32
    return %y : i32
  }
```

这是输入文件，不是 C++ 源文件：

| 项目 | 内容 |
|---|---|
| 输入 | `wdir/test/add.mlir` |
| 文件格式 | MLIR 文本格式 |
| 提供者 | 手工编写，或由前端/上一个 compiler pass 生成 |
| 用途 | 被 `tutorial-opt` parser 转成内存中的 Module/Operation 对象 |

```text
ModuleOp
└── func.func
    └── Region
        └── Block（参数 %x）
            ├── arith.constant -> OpResult %c1
            ├── arith.addi     -> OpResult %y
            └── func.return    -> OpOperand 使用 %y
```

`Value` 是 `OpResult` 或 `BlockArgument` 的统一句柄，不是 C++ `int`；
`OpOperand` 是一次 use，`Region` 是 Block 列表，Block 内的 Operation 是链表。

## Step 2：把课件 C++ API 放进一个 pass 源文件

### 2.1 本 step 做什么

这一阶段才真正写课件中的 C++。代码使用 MLIR C++ API 修改 Step 1 的内存 IR，
例如遍历 `arith.addi`、读取 operand、创建新 Operation 或替换 use。它不是
修改 `add.mlir` 文本；它修改 parser 建立的对象，最后由 printer 输出新文本。

### 2.2 先学会读 C++ API 签名

不要把函数名当成魔法。先按下面的格式读一个调用：

```cpp
对象.函数(参数1, 参数2)
```

`.` 表示对象本身调用成员函数；`->` 表示对象是指针；括号中的参数是传给
函数的输入；返回值由等号左边的变量接收。比如：

```cpp
mlir::Value lhs = add.getLhs();
```

读作：“对 `add` 调用 `getLhs()`，不需要参数，返回一个 `Value`，把它命名为
`lhs`。”本讲最常用的函数先按“用途 -> 参数 -> 返回值”列出：

| 调用 | 功能 | 参数 | 返回值/注意 |
|---|---|---|---|
| `func.walk(callback)` | 递归访问函数内部的 operation | 一个回调函数；回调参数是当前 operation | 无；回调会被调用多次 |
| `add.getLhs()` / `add.getRhs()` | 取 `arith.addi` 的第 0/1 个输入 | 无 | `Value` |
| `op->getOperand(i)` | 按编号取第 `i` 个输入 | `i` 从 0 开始 | `Value`；只读查询 |
| `op->getResult(i)` | 按编号取第 `i` 个输出 | `i` 从 0 开始 | `OpResult` |
| `value.getType()` | 查询 SSA 值的类型 | 无 | `Type` |
| `value.getDefiningOp()` | 找到定义这个值的 operation | 无 | `Operation *`；BlockArgument 没有定义 operation，可能为空 |
| `op->getOpOperand(i)` | 取得第 `i` 条 use 边 | `i` 从 0 开始 | `OpOperand &`，可修改 |
| `use.set(newValue)` | 将这条 use 改为使用新值 | 一个 `Value` | 无；会维护 use-def 链 |
| `value.replaceAllUsesWith(newValue)` | 批量替换所有 use | 一个新 `Value` | 无 |
| `result.use_empty()` | 判断 result 是否没有使用者 | 无 | `bool` |
| `op->erase()` | 从父 Block 移除并销毁 operation | 无 | 无；只用于已插入 IR 的 operation |
| `op->destroy()` | 直接销毁 operation 内存 | 无 | 无；只用于 detached operation |
| `builder.setInsertionPointAfter(anchor)` | 设置后续插入位置 | 一个锚点 operation | 无 |
| `builder.create<Op>(loc, args...)` | 创建并插入 typed operation | 位置 `loc` 和该 Op 的构造参数 | 新建的 typed operation |
| `op->dump()` / `value.dump()` | 调试打印对象 | 无 | 无；通常写 stderr |

查不到函数时，先按对象类型找 MLIR 头文件：`Operation *` 看
`MLIR_ROOT/include/mlir/IR/Operation.h`，`Block *` 看
`MLIR_ROOT/include/mlir/IR/Block.h`，`Region &` 看
`MLIR_ROOT/include/mlir/IR/Region.h`，Builder/rewriter 看
`MLIR_ROOT/include/mlir/IR/Builders.h` 和 `mlir/IR/PatternMatch.h`。这些文件
就是 API 的“字典”；课件最后一页也建议阅读这些头文件和生成的
`build/tutorial/dialect/*.inc`。

先只掌握四个动作就够开始练习：

```text
查：getOperand / getResult / getType
建：builder.create<...>(位置, 参数...)
改：use.set(...) 或 replaceAllUsesWith(...)
删：op->erase()
```

下面代码中的 `i`、`loc`、`context`、`builder` 各自代表：索引、源代码位置、
MLIRContext 和创建器；它们不是隐含的全局变量，需要由 pass 或调用者提供。

### 2.3 建议的学习顺序

不要一开始就背完整 pass。每次只增加一种动作：

```text
第 1 次：只调用 add.dump()，确认 walk 找到了哪些 operation。
第 2 次：调用 getLhs()/getRhs()/getType()，只查询，不修改。
第 3 次：使用 builder.create<...>() 创建一个 operation，并观察打印结果。
第 4 次：使用 use.set(...) 或 replaceAllUsesWith(...) 修改一条/全部 use。
第 5 次：确认 result.use_empty() 后，再调用 erase() 删除无用定义。
```

每次只改变 `wdir/tutorial/passes/SimplifyAdd.cpp` 的一小段代码，输入仍然是
`wdir/test/add.mlir`。这样可以把“C++ 语法问题”“MLIR API 问题”和“构建/注册
问题”分开定位。

把这段程序按行翻译成白话：

```text
PassWrapper<...>       = 声明“这是一个 pass”，MLIR 负责调度它
OperationPass<FuncOp>  = 这个 pass 的 getOperation() 是一个 FuncOp
runOnOperation()       = pass 真正开始工作的入口
getOperation()         = 取当前正在处理的函数
func.walk(callback)    = 遍历函数内所有 operation；每找到一个 AddIOp 就调用 callback
add.getLhs()/getRhs()  = 取加法左、右输入，都是 Value
getOpOperand(1)        = 取第 1 号输入对应的 use 边（编号从 0 开始）
use.set(lhs)           = 把右输入改成左输入
```

注意 `walk` 的参数不是一个普通数值，而是一个“收到当前 operation 后要执行的
小函数”。因此下面的 `[&](mlir::arith::AddIOp add) { ... }` 可以读成：

```text
每遇到一个 arith.addi，就把它命名为 add，并执行大括号里的代码。
```

这段 C++ 的输入和输出是 **内存对象**，不是文件：

```text
输入对象：FuncOp、AddIOp、Value、OpOperand
工具/运行者：MLIR PassManager 调用 runOnOperation()
输出对象：被修改的 FuncOp/ModuleOp
```

### 2.5 课件 API 与代码对应关系

这里开始不再给“无归属的代码片段”。下面先创建一个**完整的 C++ 文件**，然后
在这个文件内部逐段学习 API。

#### 文件 A：完整的 pass 源文件

新建并编辑：

```text
wdir/tutorial/passes/SimplifyAdd.cpp
```

把下面全部内容保存到这个文件。这个文件可以作为本 step 的唯一 C++ 源码输入：

```cpp
// 文件：wdir/tutorial/passes/SimplifyAdd.cpp
#include <memory>

#include "mlir/Dialect/Arith/IR/Arith.h"
#include "mlir/Dialect/Func/IR/FuncOps.h"
#include "mlir/IR/PatternMatch.h"
#include "mlir/Pass/Pass.h"
#include "mlir/Pass/PassRegistry.h"

namespace mlir {
void registerSimplifyAddPass();
}

namespace {

struct SimplifyAddPass
    : mlir::PassWrapper<SimplifyAddPass,
                        mlir::OperationPass<mlir::func::FuncOp>> {
  // 这两个函数给命令行 pipeline 提供 pass 名称和帮助文本。
  mlir::StringRef getArgument() const override { return "simplify-add"; }
  mlir::StringRef getDescription() const override {
    return "Print and demonstrate C++ API operations on arith.addi";
  }

  // MLIR PassManager 会调用这个函数。
  void runOnOperation() override {
    mlir::func::FuncOp function = getOperation();

    // walk(callback)：遍历 function 内的 operation。
    // 每发现一个 arith.addi，就把它作为参数传给下面的大括号。
    function.walk([&](mlir::arith::AddIOp add) {
      // getLhs()/getRhs()：取 add 的两个输入，返回 Value。
      mlir::Value lhs = add.getLhs();
      mlir::Value rhs = add.getRhs();

      // getType()：查询 Value 的类型；dump()：把对象打印到 stderr。
      lhs.getType().dump();

      // getDefiningOp()：查询 rhs 是由哪条 operation 定义的。
      // BlockArgument 没有 defining operation，因此返回值可能为空。
      if (mlir::Operation *definition = rhs.getDefiningOp())
        definition->dump();

      // getOpOperand(1)：取得第 1 号输入对应的 use 边（编号从 0 开始）。
      // set(lhs)：把这条 use 改为使用 lhs，并维护 use-def 链。
      mlir::OpOperand &rhsUse = add->getOpOperand(1);
      rhsUse.set(lhs);

      // 下面是“创建 detached operation”的完整写法，默认不执行。
      // 它只是演示课件中的 OperationState API，不能和上面的 rhsUse.set
      // 同时作为真实优化规则执行。
      //
      // mlir::Location loc = add.getLoc();
      // mlir::OperationState state(loc, "arith.addi");
      // state.addOperands({lhs, rhs});
      // state.addTypes(lhs.getType());
      // mlir::Operation *detached = mlir::Operation::create(state);
      // detached->dump();
      // detached->destroy();
    });
  }
};

} // namespace

// 文件外的注册函数，供 tutorial-opt.cpp 调用。
namespace mlir {
void registerSimplifyAddPass() {
  registerPass([]() -> std::unique_ptr<Pass> {
    return std::make_unique<::SimplifyAddPass>();
  });
}
} // namespace mlir
```

这份文件的输入/输出不是文件，而是运行时对象：

```text
输入对象：当前 FuncOp，以及其中的 AddIOp/Value/OpOperand
入口函数：SimplifyAddPass::runOnOperation()
修改动作：rhsUse.set(lhs)
输出对象：被修改的 FuncOp；之后由 printer 写成 .mlir
```

文件中的 API 与参数可以这样读：

```text
function.walk(callback)
  function = 当前函数；callback = 每遇到一个 operation 时执行的小函数

add.getLhs() / add.getRhs()
  无参数；返回左/右输入 Value

add->getOpOperand(1)
  参数 1 是 operand 编号，从 0 开始；返回可修改的 OpOperand 引用

rhsUse.set(lhs)
  参数 lhs 是新的 Value；把这一次使用改为 lhs

rhs.getDefiningOp()
  无参数；返回定义 rhs 的 Operation*，没有定义者时可能为空
```

### 创建 Operation 的代码放在哪里？

仍然放在同一个文件：

```text
wdir/tutorial/passes/SimplifyAdd.cpp
```

它不是另一个文件，也不是直接粘贴到 `.mlir` 文件。把上面完整文件中的“默认不
执行”代码取消注释后，代码含义是：

```cpp
mlir::Location loc = add.getLoc();
mlir::OperationState state(loc, "arith.addi");
state.addOperands({lhs, rhs});
state.addTypes(lhs.getType());
mlir::Operation *detached = mlir::Operation::create(state);
detached->dump();
detached->destroy();
```

逐行对应：

```text
add.getLoc()                 -> 取新 operation 的源代码位置
OperationState(loc, name)    -> 描述“要创建名为 arith.addi 的 operation”
addOperands({lhs, rhs})      -> 设置两个输入；花括号内是参数列表
addTypes(lhs.getType())      -> 设置一个结果类型
Operation::create(state)     -> 分配 detached operation，不插入 Block
detached->dump()             -> 调试打印
detached->destroy()          -> 释放 detached operation
```

如果要创建并插入，而不是 detached，仍在这个文件中使用 Builder：

```cpp
mlir::OpBuilder builder(add.getContext());
builder.setInsertionPointAfter(add);
auto newAdd = builder.create<mlir::arith::AddIOp>(add.getLoc(), lhs, rhs);
// newAdd 已经插入父 Block；删除时使用 newAdd->erase()，不要 destroy()。
```

`setInsertionPointAfter(add)` 的参数是锚点 operation；
`create<AddIOp>(location, lhs, rhs)` 的参数依次是位置、左输入、右输入。

### 查询、替换和删除也放在哪里？

同样放在：

```text
wdir/tutorial/passes/SimplifyAdd.cpp
```

例如，加入 `runOnOperation()` 的 `walk` 回调中：

```cpp
mlir::Value resultValue = add.getResult();
mlir::OpResult result = add->getResult(0);
mlir::Block *block = add->getBlock();

if (result.use_empty())
  result.getDefiningOp()->erase();
```

含义是：`getResult()` 取结果，`getBlock()` 取父 Block，`use_empty()` 判断
结果有没有使用者，`erase()` 从父 Block 移除并销毁 operation。只有确认 operation
没有需要保留的结果时才允许这样删除。

遍历并修改全部 use 也放在同一个 pass 文件：

```cpp
for (mlir::OpOperand &use :
     llvm::make_early_inc_range(resultValue.getUses())) {
  use.set(lhs);
}
```

这里 `resultValue.getUses()` 是 use 列表，`make_early_inc_range` 允许循环中
修改列表，`use.set(lhs)` 把每一条 use 改为 lhs。更直接的等价写法是：

```cpp
resultValue.replaceAllUsesWith(lhs);
```

### Block、Region、Type、Attribute 的代码放在哪里？

也放在 `wdir/tutorial/passes/SimplifyAdd.cpp`，因为它们都是 pass 执行时对内存
IR 的查询或修改：

```cpp
mlir::Region &region = function.getBody();
mlir::Block &entry = region.front();
for (mlir::Operation &operation : entry)
  operation.dump();

mlir::OpBuilder builder(function.getContext());
builder.setInsertionPointToEnd(&entry);
mlir::Type i16 = builder.getI16Type();
mlir::Attribute attr = builder.getI64IntegerAttr(42);
add->setAttr("answer", attr);
```

它们分别表示：`getBody()` 取函数 Region，`front()` 取第一个 Block，范围
`for` 遍历 Block 中的 operation，`setInsertionPointToEnd` 把插入光标放到末尾，
`getI16Type`/`getI64IntegerAttr` 创建 Type/Attribute，`setAttr` 给 operation
设置名为 `answer` 的属性。

## Step 3：把 pass 加入 `tutorial-opt` 并运行

### 3.1 本 step 做什么

### 3.2 手动修改的文件

```cpp
#include "mlir/IR/MLIRContext.h"
#include "mlir/InitAllDialects.h"
#include "mlir/InitAllExtensions.h"
#include "mlir/InitAllPasses.h"

  mlir::registerAllDialects(registry);

}
```

这次需要手工修改的完整源文件只有：

```text
wdir/tutorial/tutorial-opt.cpp
```

不要把这段代码写到 `build/tutorial/tutorial-opt`；后者是编译器生成的二进制。
也不要把 pass 代码写进 `wdir/test/add.mlir`；`.mlir` 只能写 IR 文本。

这段入口代码中的函数含义是：

| 函数 | 参数 | 作用 |
|---|---|---|
| `registerAllDialects(registry)` | 一个 `DialectRegistry &` | 把 MLIR 自带 dialect 加入注册表，使 parser 认识 `func.func`、`arith.addi` 等名字 |
| `registerAllPasses()` | 无 | 把 MLIR 自带 pass 注册到全局 pass 注册表 |
| `registry.insert<TutorialDialect>()` | dialect 的 C++ 类型 | 把本项目的 dialect 放进这个工具使用的注册表 |
| `registerSimplifyAddPass()` | 无 | 本项目自己提供的函数；把 `SimplifyAddPass` 的名字和构造方法注册进去 |
| `MlirOptMain(argc, argv, text, registry)` | 命令行参数、帮助文本、注册表 | 读取 `.mlir`、建立 Module、运行命令行指定的 pipeline、打印结果 |
| `asMainReturnCode(result)` | `MlirOptMain` 的返回结果 | 转成操作系统认识的 `main` 返回码 |

`argc` 是命令行参数个数，`argv` 是参数字符串数组。例如命令
`tutorial-opt test/add.mlir -o out.mlir` 会把输入路径和 `-o` 传给
`MlirOptMain`；`registry` 告诉 parser 和 pass manager 可以使用哪些 dialect/pass。

这里的 `registerSimplifyAddPass()` 不是 MLIR 自动提供的函数，而是你在
`wdir/tutorial/passes/SimplifyAdd.cpp` 中实现并导出的注册函数。若忘记这一层，
即使 `.o` 成功链接，命令行也找不到 `simplify-add` 这个 pass。

如果只想使用 MLIR 自带 pass，可以不改这个文件；本讲的自定义 pass 则必须在
这里或等价的注册位置注册。不要修改 `build/tutorial/tutorial-opt`，它是生成物。

### 3.3 编译和链接输入输出

输入：

```text
wdir/tutorial/tutorial-opt.cpp              # 修改后的工具入口
wdir/tutorial/passes/SimplifyAdd.cpp.o      # Step 2 输出
wdir/build/tutorial/dialect/libTutorialDialect.a
MLIR_ROOT/include/mlir/**/*.h
MLIR_ROOT/lib/libMLIR.so、libLLVM.so 等库
```

工具：系统 `c++` 和链接器；本 step 不调用 `mlir-tblgen`。以手工构建为例：

```bash
c++ -std=c++17 -I"$MLIR_ROOT/include" -I"$PWD/tutorial" \
  -I"$PWD/build/tutorial" -c tutorial/tutorial-opt.cpp \
  -o build/tutorial/tutorial-opt.cpp.o

c++ build/tutorial/tutorial-opt.cpp.o \
  build/tutorial/passes/SimplifyAdd.cpp.o \
  build/tutorial/dialect/libTutorialDialect.a \
  -L"$MLIR_ROOT/lib" -Wl,-rpath,"$MLIR_ROOT/lib" \
  -lMLIR -lLLVM -o build/tutorial/tutorial-opt
```

输出：

```text
wdir/build/tutorial/tutorial-opt.cpp.o
wdir/build/tutorial/tutorial-opt             # 最终可执行工具（覆盖旧生成物）
```

链接完成后的目录树：

```text
wdir/
├── .venv/
├── build/tutorial/
│   ├── dialect/
│   │   ├── *.inc                       # Step 1 生成
│   │   └── libTutorialDialect.a        # Step 2 生成
│   ├── passes/
│   │   └── SimplifyAdd.cpp.o           # Step 2 生成
│   ├── tutorial-opt.cpp.o              # Step 3 生成
│   └── tutorial-opt                   # Step 3 生成的最终工具
├── tutorial/
│   ├── dialect/                        # step1/2 的源码
│   ├── passes/SimplifyAdd.cpp           # 本讲手写/修改
│   └── tutorial-opt.cpp                # 本讲修改/注册 pass
└── test/add.mlir                       # 本讲输入
```

### 3.4 运行：输入和输出文件终于重新变成文件

```bash
build/tutorial/tutorial-opt \
  test/add.mlir \
  --pass-pipeline='builtin.module(func.func(simplify-add))' \
  -o /tmp/add.out.mlir
```

```text
输入文件： wdir/test/add.mlir
调用工具： wdir/build/tutorial/tutorial-opt
中间过程： parser -> ModuleOp -> PassManager -> C++ API 修改 IR -> printer
输出文件： /tmp/add.out.mlir
诊断输出： stderr；可加 -mlir-print-ir-before-all/-after-all 调试
```

如果只运行：

```bash
build/tutorial/tutorial-opt test/add.mlir
```

则通常只有解析和打印，没有自定义 pass 的 IR 修改。`SimplifyAdd.cpp` 中的
C++ API 只有被 Step 3 编译、链接、注册并加入 pipeline，才会真正执行。

## 4. 三个 step 的变化总表

| Step | 手写/修改路径 | 输入 | 工具 | 输出 |
|---|---|---|---|---|
| 1 | `wdir/test/add.mlir`（新增） | MLIR 文本 | `tutorial-opt` | 解析/打印的 MLIR |
| 2 | `wdir/tutorial/passes/SimplifyAdd.cpp`（新增） | C++ 源码、MLIR 头文件、step1-3 生成 `.inc` | `c++ -c` | `build/tutorial/passes/SimplifyAdd.cpp.o` |
| 3 | `wdir/tutorial/tutorial-opt.cpp`（修改） | driver `.cpp`、pass `.o`、dialect `.a`、MLIR 库 | `c++` + linker | `build/tutorial/tutorial-opt` |
| 3 运行 | 不再修改源码 | `wdir/test/add.mlir` | `tutorial-opt` + pass pipeline | `/tmp/add.out.mlir` |

务必区分：

```text
wdir/tutorial/*.cpp       = 你手写/修改的 C++ 源代码
wdir/build/**/*.o/.a      = 编译器生成的二进制中间产物
wdir/build/tutorial-opt   = 编译器生成的可执行文件
wdir/test/*.mlir          = 编译器的 IR 文件输入/输出
```

## 5. 新手最容易犯的错误

1. 把 `build/` 下的 `.inc` 当作手写源代码修改。它们来自 `mlir-tblgen`，应
   修改 `wdir/tutorial/dialect/*.td` 后重新生成。
2. 把 `OperationState::create` 生成的 detached operation 当成已经插入 IR 的
   operation。需要父 Block 时使用 Builder 或显式插入。
3. 对已插入 Block 的 operation 调 `destroy()`。应先 `erase()`，否则会破坏链表。
4. 修改 use 链时普通遍历并删除当前元素。使用 `make_early_inc_range` 或
   `PatternRewriter`。
5. 只编译 `SimplifyAdd.cpp`，却忘记在 `tutorial-opt.cpp` 注册并链接 pass；这样
   可执行文件根本不会调用你的 C++ 代码。
6. 把 `.mlir` 输入误认为 C++ API 的直接参数。API 接收的是 parser 建立的
   `Operation`/`Value` 对象；`.mlir` 只是进入和离开编译器的序列化文件。
